## 5. The 12 nodes in plain words (all in crop_trigger/agent.py)

1. **intake** (`intake`, :113): checks the policy and primary CSV exist, splits the policy into clauses and builds the search index; halts if not.
2. **retrieve_rules** (`retrieve_rules`, :139): looks up the phase clauses, stations, period, cap and dry-day rule through the retrieval loop and turns them into rule objects with `rules.py`; halts if a clause cannot be found.
3. **load_validate** (`load_validate`, :200): loads both station CSVs with `tools.load_weather_csv` and profiles them (stations, units, dates).
4. **make_plan** (`make_plan`, :226): looks at the data and decides which extra steps are needed: units, missing, cross, then always compute and verify.
5. **retrieve_support** (`retrieve_support`, :259): fetches only the extra clauses the plan needs (unit factors, fill limit).
6. **remediate** (`remediate`, :283): converts units, fills up to the allowed number of gaps from the secondary station, and marks a phase undetermined if it cannot.
7. **compute** (`compute`, :354): runs the Decimal calculator `engine.compute_phase` on each ready phase to get index, trigger and payout.
8. **verify** (`verify`/`_verify`, :375/:383): recomputes each result independently (`verify.py`), checks the numbers appear in the clause text, and loops back to compute once on a mismatch.
9. **cross_check** (`cross_check`, :418): recomputes with the secondary station and refers to a human if the trigger outcomes differ.
10. **decide** (`decide`, :447): turns phase results into TRIGGER_MET, TRIGGER_NOT_MET or CANNOT_DETERMINE and applies the overall cap; no payout figure if undetermined.
11. **human_gate** (`human_gate`, :477): sets the status to AWAITING_HUMAN_REVIEW for undetermined cases (a flag the UI uses; it does not block).
12. **write_report** (`write_report`, :486): builds the markdown and JSON report with `report.build_report`.

Explainability flags: 90+ functions and classes lack docstrings (agent.py has 19, rag.py 14, engine.py 11, rules.py 11). The hardest to explain are `retrieve_rules` (59 lines), `remediate` (69 lines), `compute_phase` (53 lines), `build_report` (74 lines, no docstring), `AgentState` (50 lines, no docstring), `decide` and `cross_check` (no docstrings), and `cli.main` (no docstring). `remediate` mixes unit handling, station checks, gap filling and reason codes in one function. The built-in runner, `EDGES` router table and langgraph builder are small and easy to explain.

## 6. Limitations a reviewer could probe

- Rule extraction is regex-based and tied to this policy layout (rules.py:37-72); a differently worded policy would fail or abstain. LLM extraction is only a cross-check, not the primary path.
- Fill limit, dry-day threshold, stations, unit factors and period are read from the policy text, but phase types are recognised by title keywords ("cumulative rainfall deficit", "dry spell", excess rainfall); a fourth phase type would need code.
- The human gate does not wait for anything. Recording a review only appends to the audit record in `runs/`; it does not recompute or change the decision.
- The Anthropic client is untested (README says so). The Ollama client was tested once against a local model; the LLM report summary path is exercised only with fakes.
- The 38 cases, stress generator and mutation check share the author's reading of the policy (README admits this). Mutation check covers 4 bugs.
- Streamlit was only tested headlessly (AppTest per README, server start/health by me), not by eye.
- Everything is synthetic; no real station data, no real policy.
- Each run writes a trace into `traces/` in the project folder, so repeated runs accumulate files.
- `python -m crop_trigger.cli` only works from the project root.
